## ข้อ 1 — เมื่อ noise เพิ่ม C1 จะมี switching count เปลี่ยนอย่างไร

**คาด:** switching count ของ C1 เพิ่มขึ้นตาม σ โดยเพิ่มแบบใกล้เคียงสัดส่วนกับ σ

เหตุผล: C1 เทียบค่า raw กับ T = 0.35 m โดยตรง ระยะจริงเปลี่ยนเพียง 0.00175 m ต่อ sample (0.0875 m/s × 0.02 s) ดังนั้นเมื่อ noise ใหญ่กว่าระยะที่เปลี่ยนต่อ sample หลายเท่า ค่า raw จะข้าม T กลับไปกลับมาหลายครั้งในช่วงใกล้ crossing ทั้งขาเข้าและขาออก ถ้า noise เป็นอิสระต่อกันในแต่ละ sample จำนวนครั้งที่ข้ามต่อหนึ่ง crossing ประมาณ 1.13 × σ / 0.00175

| σ (m) | คาด switching count ต่อ trial | หมายเหตุ |
|---|---|---|
| 0.00 | 2 พอดี | ไม่มี noise จึงไม่มี chatter |
| 0.01 | ประมาณ 13 (extra switches ประมาณ 11) | ประมาณ 6 ครั้งต่อ crossing |
| 0.03 | ประมาณ 40 หรือมากกว่า | ที่ 0.03 m ช่วง 8–12 s ที่ระยะจริง 0.235–0.265 m อาจมี raw ข้าม 0.35 m เป็นครั้งคราว (ห่าง 2.8σ) |

ตัวเลขข้างบนเป็นการประมาณคร่าว ๆ เพื่อใช้เทียบกับผลจริง ทิศทางที่มั่นใจคือเพิ่มขึ้นตาม σ

## ข้อ 2 — C2 จะลด false trigger โดยแลกกับ latency หรือ recovery time อย่างไร

**คาด:** C2 ลด false trigger และ extra switches เหลือใกล้ 0 ที่ σ = 0.01 m แต่ latency เพิ่มขึ้นเป็นประมาณ 0.4 s ทั้ง enter และ exit

เหตุผล:

- Hysteresis: C2 เข้า NEAR เมื่อ filtered < 0.32 m ซึ่งต่ำกว่า T อยู่ 0.03 m ที่ความเร็ว 0.0875 m/s ใช้เวลา ≈ 0.34 s ฝั่ง exit ที่ 0.38 m ก็เลื่อนเวลาไปเท่ากัน ≈ 0.34 s
- Low-pass filter β = 0.25 ทำให้ค่า filtered ตามหลังค่าจริงประมาณ (1 − β)/β × dt = 0.06 s
- รวมแล้ว latency ของ C2 ≈ 0.34 + 0.06 ≈ 0.4 s ส่วน C1 ที่ใช้ raw ควรมี latency ใกล้ 0 (อาจเป็น 0 เพราะ noise ทำให้ state ถูกต้องก่อนถึง crossing)
- Recovery time: C2 ≈ latency ของมัน (ประมาณ 0.4 s) เพราะไม่ chatter ส่วน C1 ที่ σ = 0.01 อาจไม่ได้เร็วกว่า C2 มาก เพราะต้องรอให้ state ถูกต้องต่อเนื่อง 0.5 s หลังพ้นช่วง chatter ประมาณ ±0.23 s รอบ crossing

## ข้อ 3 — เมื่อเพิ่ม sensor delay 300 ms การตอบสนองจะเลื่อนจากเหตุการณ์จริงอย่างไร

**คาด:** latency เพิ่มขึ้นใกล้ 0.3 s แบบบวกเพิ่ม (C1 ประมาณ 0.3 s, C2 ประมาณ 0.4 + 0.3 = 0.7 s)

เหตุผล: delay อยู่เฉพาะเส้นทาง sensor controller จึงเห็นระยะของเวลา t − 0.3 s ทำให้ทุก event เลื่อนไปประมาณ 300 ms ส่วน noise และ hysteresis ไม่เปลี่ยน

ผลข้างเคียงที่คาด: delay 300 ms = 15 sample ดังนั้น 15 sample แรกของทุก trial จะเป็น invalid (`MISSING_OR_DELAY_BUFFER`) และ controller ใช้ safe command = 0 โดย state ค้างที่ FAR ส่วน delay 100 ms จะมี invalid 5 sample และ delay 0 ms ไม่มี
